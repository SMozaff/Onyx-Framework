# Native UI Smoke Evidence and Release Manifest Contract

## Purpose

This procedure is the Milestone 4 quality gate for the **Staff** and **Admin** Tauri frontends. It separates evidence that can be reproduced on any Linux CI runner from evidence that must be collected on each native target. A compiled frontend bundle is not represented as proof that a native window launched; the evidence manifest states exactly which command was observed.

## Evidence levels

| Level | Environment | Required check | What it proves | What it does not prove |
|---|---|---|---|---|
| 1. Frontend smoke | Linux CI | `npm ci` and `npm run build` in each UI directory | TypeScript, bundling, shared components, and static asset references compile for Staff and Admin. | Tauri process startup, IPC, platform integrations, or a native window. |
| 2. Tauri build matrix | GitHub-hosted Linux, macOS, Windows release debug dispatch | Existing `release.yml` desktop build matrix, run with `debug_build=true` and no release tag | The actual Tauri CLI reaches each target build/bundle path without publication. | A user completing a post-launch workflow. |
| 3. Native runtime smoke | Target OS with supported desktop prerequisites | Launch the debug binary, exercise startup/session screen, login/configuration recovery, one navigation route, and one approval dialog | The executable opens and the named user-visible flows work on that target. | Full end-to-end server compatibility or production signing/notarization. |

## CI artifact contract

The `native-ui-evidence` CI job writes `artifacts/ui-evidence/native-ui-frontend-smoke.json` only after both frontend builds pass. The manifest is generated by `scripts/collect-ui-evidence.mjs` and records the exact commit, platform, runner, commands, result, and GitHub run identifiers. It is uploaded as a CI artifact and retained under the workflow’s artifact policy.

> The manifest’s `runtime_claim` must remain present. It prevents a frontend-only check from being misreported as a successfully launched Tauri application.

## Target-native execution procedure

For each shell and target, a reviewer starts from the commit under review and uses the repository’s existing debug build path. The reviewer records the generated evidence file and attaches a screenshot/video only when policy permits test data to appear in it.

| Step | Staff shell | Admin shell | Acceptance condition |
|---|---|---|---|
| Build | `npm ci && npm run build` in `crates/bins/desktop-shell/ui` and the existing Tauri debug build path | `npm ci && npm run build` in `crates/bins/admin-shell/ui` and the existing Tauri debug build path | Build command exits `0`; manifest names exact target and commit. |
| Startup | Open binary with no stored session. | Open binary with no stored session. | Safe startup error or sign-in path; no raw exception is shown. |
| Recovery | Configure/verify server address, then retry. | Select local/network server option, test address, then retry. | Failure is actionable; invalid/unreachable address is not silently saved. |
| Navigation | Reduce width if applicable; open/close navigation with keyboard and focus. | Navigate to Settings then back. | Focus and route handoff are observable; no inaccessible dead-end. |
| Decision | Open test approval dialog and use Escape/Tab. | Verify an Admin command/query failure renders safe copy. | Named dialog semantics/focus behavior and safe error copy are observed. |

## Release boundary and known limitation

No release tag is created by this procedure. The manual debug dispatch preserves the existing safe behavior: release-image and publication paths remain skipped without a `v*` tag.

The pre-existing macOS application icon defect remains a separate asset dependency: the Tauri build reaches the DMG icon-processing stage but fails when a bundle icon is not RGBA-compatible. This evidence procedure records that failure accurately and does not downgrade it into a UI runtime pass. Correcting the application icons remains a separate scoped product/asset task.

## Evidence retention checklist

Each completed matrix or native smoke run must preserve the following:

- commit SHA and branch;
- shell (`staff` or `admin`) and target OS/architecture;
- executed command and exit status;
- CI run URL or reviewer-controlled evidence location;
- generated manifest artifact;
- any known limitation or skipped criterion; and
- reviewer identity and date when a human target-native check is performed.
